---
title: Protect the web UI with a password
description: Turn on optional sign-in for helenus ui, create users from the command line, and sign everyone out when a password changes.
---

By default `helenus ui` listens on `127.0.0.1:4042` and has no sign-in, because only your own machine can reach it. Turn sign-in on when other people or other machines may reach the port.

## Create a user

Users are created only from the command line. The web UI has no sign-up page.

```bash
helenus user add alice
```

You are asked for the password twice with echo off. It must be at least 12 characters. In a script, read it from stdin instead:

```bash
printf '%s\n' "$PASSWORD" | helenus user add alice --password-stdin
```

Usernames are unique and not case-sensitive. `helenus user list` shows each user and their last sign-in, and `helenus user remove alice` deletes one (add `--yes` to skip the confirmation).

## Start the UI with sign-in

```bash
helenus ui --auth
```

You can also set `HELENUS_AUTH=true`, or `ui.auth.enabled: true` in `config.yaml`. The UI then shows a sign-in screen. If no user exists yet, `helenus ui --auth` stops and tells you to run `helenus user add`.

A session lasts 12 hours and is renewed quietly while you work. If it ends, Helenus returns to the sign-in screen and keeps your open tabs; sign in again and carry on. With sign-in on, your open query tabs and their text are saved per user and profile and come back the next time you sign in.

Use the user menu at the right of the title bar to sign out.

## Change a password or remove a user

```bash
helenus user passwd alice
```

Changing a password signs that user out of every browser straight away, and so does `helenus user remove`. Their next request returns to the sign-in screen.

## Where users are stored

Users live in the SQLite file shared by every `helenus ui` run (`-D, --db`, default in the XDG data directory). Point `helenus user` at the same file with `--db` if you moved it.
